## 4. Decisions made

1. **One Summit plan per elected `ServiceItem`.** The two `Ins125` PremiumPath rails become **two
   separate catalogue items**, not one item fanning out — decisive reason: **an employer without Presidio
   must not get a Presidio plan**. ⚠️ **Enforced by a named unique constraint, not the primary key**
   (`uq_summit_plan_template_map_psp_service`), so if fan-out is ever wanted the reversal is
   `DROP INDEX` against live rows rather than rebuilding a table whose identity changed.
2. **The mapping moved to a PSP-scoped table with `SUMMIT_PLAN_TEMPLATES` as fallback.** An empty table
   behaves exactly as before, which is what made V095 safe to ship ahead of the screen that writes to it.
3. ⭐ **Grace is a computed date, not a day count.** §1.125-1(e) is a **calendar** rule and the length it
   implies varies with the plan year end month — **74, 77 and 74 days** for the three year-ends tested.
   **No fixed count can express it**, and S31-H's 75-day default resolved to **16 March** for a
   31 December year end: **one day past the statutory maximum**, every non-leap year.
4. **Plan identity does not carry the plan year.** `Import Plan ID` is now `{employerKey}-{keySegment}`
   at **both** composition sites. **T185 retired — its premise was wrong.**
5. ⭐ **Renewal plan years are assigned through Summit's own UI action, not by import** (Kevin,
   2026-09-08). **File 2 is a one-time plan-creation artifact, not a renewal artifact.** This is why
   decision 4 needed no validation from renewal behaviour — the scenario T185 was protecting against does
   not arise through this file at all.
6. **A carryover FSA is omitted from file 2 and reported**, because carryover has **no element anywhere**
   in the `Employer CDH Plan` template. The export does not fail; every other plan emits.
7. **A zero-row export refuses** rather than writing an empty file — reusing the existing 400 by adding a
   **second** refusal, so the original all-unmapped case keeps its output byte-for-byte. That page is the
   operator's only route to a `ServiceItem` id without SQL (D-90) and could not be reworded.

## 5. The three-tier model — it governs future work

| Tier | Elements | Home |
|---|---|---|
| **Fixed per plan type** | Run-out enabled / by-date / days, terminated run-out type and days; **and everything in Claim Processing Rules** | Config, or the Summit template itself |
| **Per sale** | Grace enabled and its date, plan year, effective date | Application answers |
| **Not importable at all** | FSA **carryover** and its amount; HRA, MERP and DRiP reimbursement logic needing deductibles and percentages | Hand-built in Summit; **AMS reports rather than attempts** |

The third tier is the one worth remembering: **the correct behaviour for something AMS cannot express is
to skip it and say so loudly**, not to emit a partial row and not to fail the whole export.

## 6. New assumptions, each with reversal cost

- **`SUMMIT_CDH_GRACE_FIELDS` can change emitted bytes even with `SUMMIT_CDH_OPTIONAL_ELEMENTS` unset** —
  a carryover plan is still omitted. **Intended**, because carryover is about importability rather than
  columns; disclosed because S31-H's stated byte-identity invariant was worded against the other key
  alone and did not cover it. **Reversal: none needed.**
- ⚠️ **The un-suffixed `Import Plan ID` upserts on re-send.** **Unproven.** AMS emits full current state
  rather than deltas, so correction re-sends are expected to be routine, and whether a re-send **updates**
  the plan or **duplicates** it has never been tested. **Reversal is cheap today and permanent once a
  real employer's plan exists**, which is why T210 is HIGH.
- **`GRACE_DAYS` now has no source and emits empty always.** The token survives only so a template
  mapping that column still binds positionally. **Reversal: delete the token.**

## 7. Contradictions found

- ⭐ **T185's do-not-touch protected a broken shape.** It reasoned that keeping the year in the key was

  after Kevin corrected the renewal premise. **The wrong version was never run.** Worth recording as the
  process working: the premise was checked before the code was written, not after it shipped.
- **`12=FSA` and `123054=HFSA` are two different service items on the same sale**, both FSA-flavoured.
  **T189/T190 in the wild** — `ServiceItem.code` is null and `description` is a stale copy, so **only the
  id distinguishes them**. This is exactly why the admin screen's picker shows ids.
